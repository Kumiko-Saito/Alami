# 婚活マッチングアプリ

婚活イベント当日、参加者が自分のスマホでお互いのプロフィールを見て、気になるお相手を最大3名まで選べるアプリです。マッチング結果（相互選択）は参加者には一切表示されず、運営だけが管理画面で確認できます。

## できること

- 参加者は「性別＋番号（男女各1〜N）＋名字（ひらがな）」で本人確認してプロフィールを登録・編集
- 同じ性別・番号を他人が名字違いで登録することはできない（本人確認）
- 登録後、異性の参加者一覧（番号タップでプロフィール表示）を閲覧
- 気になるお相手を最大3名まで選び、「決定」で確定（イベント中は何度でも選び直し可能）
- マッチング判定（相互選択）は**運営管理画面のみ**に表示。参加者には通知・表示一切なし
- 運営は `/admin.html` から、参加者一覧・誰が誰を選んだか・マッチング結果を確認
- プロフィール項目（ニックネーム・年齢・居住地…）は運営画面から追加・編集・削除・並び替え可能
- イベント終了ボタンで参加者のアクセスを停止。設定時間（既定24時間）後にプロフィール詳細を自動削除（名字とマッチング結果は残る）
- 参加者のスマホには何もインストール不要（ブラウザで開くだけ）

## 技術構成

Node.js + Express の小さな1プロセスアプリです。データは `data/db.json` に保存され（DBサーバー不要）、24時間後の自動削除もサーバープロセス内のタイマーで動きます（常駐させておく必要があります）。

## ローカルで試す

```bash
npm install
npm start
```

`http://localhost:3000` が参加者用、`http://localhost:3000/admin.html` が運営用です。初回アクセス時に管理用パスコードを設定します。

## 本番（インターネット公開）へのデプロイ

無料枠があり、Node.jsの常駐プロセスをそのまま動かせる **Render** を想定した手順です。

1. **GitHubにリポジトリを作る**
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   ```
   GitHub上で新規リポジトリを作成し、`git remote add origin <URL>` → `git push -u origin main` で push します。

2. **Renderでサービスを作る**
   - https://render.com にサインアップ（GitHubアカウントでログイン可）
   - 「New +」→「Web Service」→ 先ほどのリポジトリを選択
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: Free でOK
   - Environment: 特別な環境変数は不要（`PORT` はRenderが自動設定）

3. デプロイが終わると `https://<サービス名>.onrender.com` のようなURLが発行されます。
   - 参加者用: そのURLをそのままQRコードにして配布
   - 運営用: `https://<サービス名>.onrender.com/admin.html`

### 注意点（無料プランを使う場合）

- Renderの無料Web Serviceは、しばらくアクセスがないと自動的にスリープします。イベント開始の少し前に一度アクセスして起こしておいてください。
- 24時間後の自動削除はサーバープロセスのタイマーで動くため、**イベント終了後も24時間はサービスを起こしたまま（または定期的にアクセスして）** にしておくと確実です。スリープ中は削除タイマーが進みませんが、次にアクセスがあった時点で経過時間をチェックして削除するので、多少ずれても実害はありません。
- 無料プランのディスクは永続化されないため、**再デプロイ**するとデータが消えます（イベント中〜削除完了まで再デプロイしない）。
- 管理用パスコードは初回アクセス時にその場で設定してください（コード内にはパスコードを書き込んでいません）。

## 運営の使い方（当日の流れ）

1. `/admin.html` を開き、初回のみ管理用パスコードを設定
2. 必要ならプロフィール項目編集で項目を調整（初期状態で9項目入っています）
3. イベント名・定員（男女それぞれ何番まで）を入力して「開始する」
4. 受付で参加者に性別・番号・名字（ひらがな）を伝える
5. イベント中は参加者一覧・選択状況・マッチング結果をリアルタイムに近い形で確認できる（4秒おきに自動更新）
6. イベント終了時、「イベントを終了する」を押す
   → 参加者は即座にアクセス不可に。プロフィール・選択・マッチング結果は運営画面からまだ見える
7. 24時間後、プロフィール詳細（年齢・職業など）が自動削除される（名字とマッチング結果は残る）。早めに消したい場合は「今すぐプロフィール詳細を削除する」を使用
8. 次のイベントで使い回す場合は「完全リセットする」で参加者・選択・マッチング結果を全消去（プロフィール項目の設定は引き継がれます）

## 既知の制約

- 本人確認は「番号＋名字（ひらがな）」の組み合わせのみです。名字を他人に知られると編集・選択ができてしまいます。信頼関係のある少人数の対面イベント向けの設計です。
- 管理用パスコードは平文でサーバーのデータファイルに保存されます。高いセキュリティが必要な用途には別途対策してください。
- 24時間後の自動削除は、サーバープロセスが動き続けていること（または動いている間にアクセスがあること）が前提です。プロセスが24時間以上完全に停止していた場合、次に起動してアクセスがあった時点で削除が実行されます。
